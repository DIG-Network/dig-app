# Lane #1966 + #1965 — the recovery-phrase backup file

Two tickets, one code path (`save_phrase_file` / `write_owner_only`):

* **#1966** — a native save-file picker, so the user chooses where the plaintext seed lands
  instead of a fixed, predictable `~/dig-recovery-phrase.txt`.
* **#1965** — an explicit owner-only ACL on whatever path they choose. Windows does NOT honour
  Unix mode bits, so the `#[cfg(not(unix))]` arm's plain `fs::write` leaves the file on inherited
  profile ACLs (user + Administrators + SYSTEM).

They ship together because #1966 widens the exposure #1965 closes: a user-chosen directory is far
more likely to be synced or shared (Desktop, Documents, OneDrive) than the profile root was.

## What landed

`dig-app-core::secret_file`, a new module holding both halves:

| File | Holds |
|---|---|
| `mod.rs` | `choose_secret_file_path` — the cancel-vs-unavailable decision |
| `owner_only.rs` | `write_owner_only` + the Unix and Windows permission tests |
| `windows_acl.rs` | the protected single-ACE DACL, and the ACL inspection the tests assert on |
| `picker/{mod,windows,macos,linux}.rs` | the `SaveFilePicker` seam and the three platform dialogs |

The logic moved OUT of `crates/dig-app/src/bin/dig-app.rs`, where the crate's own manifest says
coverage is not measured. The shell now only addresses the vault and calls the core.

## The two decisions worth remembering

1. **A cancel is not a fallback.** Dismissing the dialog abandons the write. Falling back to the
   old fixed path there would write the seed somewhere the user had just declined.
2. **An unavailable dialog IS a fallback.** A headless host never got to ask, so it keeps the old
   behaviour rather than losing the feature.

## Deliberate, and worth a second opinion

macOS uses `osascript`'s `choose file name` rather than `NSSavePanel`, even though `objc2-app-kit`
is already linked — a panel needs main-thread dispatch and a modal loop that re-enters the tray's,
and none of that is verifiable from a Windows dev box. The seam is there if the panel is wanted.

## Verified

`cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -D warnings`, and
`cargo test --workspace --all-features` all green on Windows 11. The Windows ACL tests fail against
the shipped behaviour with Administrators holding `FILE_ALL_ACCESS` (2032127) on the seed file.
