# LANE 3041 — an unreadable profile body must still be givable one, and any profile must be deletable

dig_ecosystem#3041 + the dig-app half of #3068.

## Why
A user's profile store `111eb8bc…` has a chain-confirmed root `371a39b0…` whose body bytes exist
nowhere (the #3066 data-loss defect, from before the pending-body fix in 12.15.0). The profile will
not load, and the delete control does not draw, so the person is trapped with no remedy at all.

## Scope
1. `profile_edit/` — an unreadable body becomes an ordinary state with a remedy: publish a fresh
   body, retyping the content, producing a new root the chain confirms. The #3066 invariant binds:
   seal the new body to the pending file BEFORE the spend is pushed, clear only after a verified
   `getBody` round trip.
2. `profile_melt/` + the seam install in `bin/dig-app.rs` — the delete control must DRAW, for ANY
   profile including the active one.

Out of territory: `wallet/`, `dig-account` (a sibling lane owns it).
